# 실행 기록 계약

`record.schema.json`은 ITR 1.0의 정규 실행 기록을 정의한다. 다른 언어로 만든 어댑터도 이 파일의 `$defs/input`, `$defs/event`, `$defs/evidence`, `$defs/defect`를 각각 소비할 수 있다. 보고서에 필요한 수치와 링크는 완료된 시도의 `record.json`에서 읽는다.

| 계약 | 작성 시점 | 다른 데이터와의 연결 |
| --- | --- | --- |
| `input` | 실행 전 | `product`와 `revision`으로 대상을 고정한다. `baselines`의 목표·규칙·요구에는 고유 ID, 버전, 내용을 기록한다. |
| `input.checks[]` | 계획 확정 시 | `criteria`가 기준 ID를 가리키고 `pass_condition`이 실제로 관찰할 조건을 설명한다. 서로 다른 조건은 별도 검사로 나눈다. `requires`는 능력 ID, `depends_on`은 선행 검사 ID다. |
| `events[]` | 상태 전환 시 | `seq` 순으로 재생한다. 카드마다 `check_id`가 같은 이벤트의 마지막 `state`를 사용한다. `running` 카드가 같은 시점에 여러 개일 수 있다. |
| `results[]` | 검사 종료 시 | 검사 ID당 최종 상태 한 개와 관찰 근거를 남긴다. `detail`에 측정값, 차단 사유 또는 미실행 사유를 적고 수행한 검사의 증거 ID를 연결한다. |
| `evidence[]` | 관찰 기록 시 | `check_id`와 시도 폴더 기준 상대 경로, 파일 바이트 SHA-256을 보존한다. `log`, `capture`, `review`, `measurement`를 지원한다. |
| `reviews[]` | 역할별 첫 판정이 끝날 때 | 역할, 독립적으로 확인한 검사와 증거, 봉인 시각을 연결한다. 합의 이후 판정은 `decision`에 기록한다. |
| `defects[]` | 증거 대조 시 | 여러 결과가 같은 문제를 가리키면 안정적인 `fingerprint`로 묶고 관련 검사·기준·증거 ID를 유지한다. 확인된 원인과 가설은 각각 기록하며 모르면 `null`을 쓴다. |
| `approval` | 승인 요청 또는 회신 시 | 승인이나 거부에는 당사자, 시각, 대상 범위와 증거가 필요하다. 증거 파일에는 당사자 회신 또는 이를 확인할 수 있는 승인된 로컬 기록을 넣는다. |
| `previous` | 회귀, 재시도, 정정 시작 시 | 저장소 루트를 기준으로 원본 위치를 기록하고 파일 해시·회차·시도·사유를 함께 연결한다. 중단된 시도에 대해서는 예약 기록을 가리킬 수 있다. |

`precision`은 전체 계획을 기준으로 하고 `delta`는 변경점과 영향을 받는 검사를 선택한다. 생략한 검사를 보이려면 `selected: false`와 `not_run` 결과, 그 이유를 기록한다. `blocked`는 선택한 검사에 필요한 능력 또는 선행 조건을 확보하지 못했음을 나타낸다. `inspection`과 `execution`은 증거를 얻는 방법이고, `unit`·`integration`·`system`·`acceptance`·`intersystem`은 검사가 다루는 수준이다.

## 형식 검사

패키지 루트에서 `python3 schemas/validate.py <record.json 경로>`를 실행한다. 개별 입력·이벤트·증거·결함에는 `--part input`, `--part event`, `--part evidence`, `--part defect`를 지정한다. 부적합한 값이 있으면 첫 필드 경로와 사유를 표시하고 종료 코드 1을 반환한다. 이 검사기는 번들 스키마에 사용된 키워드를 Python 표준 라이브러리로 평가한다. 다른 구현에서도 JSON Schema Draft 2020-12를 사용할 수 있으며 오프셋이 있는 올바른 달력 시각을 검사해야 한다.

참조가 가리키는 ID와 실제 파일의 일치, 회차 계보와 입력 고정, 이벤트와 최종 상태 일치는 레코드 간 의미 검증의 대상이다. 외부 어댑터는 독립적으로 의존 대상을 해석하고 루트 내부 파일만 허용한 뒤 바이트 해시를 확인한다. 시각은 오프셋을 포함해 직렬화하고 사용자 표시 시 KST로 변환한다. 호스트 고유 정보를 추가하려면 최상위 `extensions` 객체를 사용한다.
