# A4 실무 QA 보고서

첫 장에서 기술 판정, 발주자·사용자 승인, 전체 검사 건수와 고유 결함 수, 대상 리비전, 기록된 결함·후속 조치를 확인한다. 전체 건수에는 범위 밖 미실행도 포함한다. 판정 사유에 적힌 선택 검사 건수는 해당 판정의 범위다. 뒷장에는 검사별 관찰, 실행 환경과 한계, 근거 식별자와 SHA-256을 모았다. 첫 장에는 기록 순서대로 결함을 최대 2건 보여 주며 전체 내용은 뒷장에서 읽을 수 있다. 계획 1.1 시도는 표준 대응 구간에 표준·항목별 결과와 검사가 없는 평가 항목을 보여 주고, 시도의 표준 목록이 승인 지문과 맞지 않으면 '표준 목록 확인 필요'만 표시한다.

기존에 PyMuPDF를 사용해 PDF를 만들던 환경에서 패키지 루트에서 실행한다. 원본 `record.json` 옆의 완결 표식과 해시가 일치해야 하며, 출력은 원본 시도 밖의 새 파일로 만든다.

```sh
python3 -B qa/print_pdf.py --profile reader examples/runs/round-0001/attempt-0001/record.json itr-qa-report.pdf
```

이 프로필은 확인용 요약과 근거 색인을 제공한다. 모든 이벤트와 증거 미리보기가 필요한 경우 기존 감사 프로필에서 `views/render.py`가 생성한 `print.html`을 사용한다.

```sh
python3 -B qa/print_pdf.py print.html itr-audit-report.pdf
python3 -B qa/check_reader_pdf.py
```

텍스트 줄바꿈은 글자 너비에 맞추고, 생성 직전 각 페이지의 추출 텍스트를 인쇄할 문자열과 대조한다. 사용한 PDF 런타임의 글꼴이 문자를 보존하지 못하면 출력 파일을 만들지 않는다. 원본 증거는 보고서가 가리키는 시도 폴더에 별도로 보관한다.
