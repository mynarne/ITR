# RC.3 검증

RC.3은 검사마다 용도에 맞는 표준을 붙이는 계획 1.1을 도입한다. 새 실행은 1.1 계획만 받으며, 1.0 계획으로 만든 기존 기록은 원래 규칙으로 검증한다. [RC.2 후속 검증](verification-rc2-followup.ko.md)의 실행 증거 2.1과 Windows 수정은 그대로 이어진다.

## 바뀐 점

- 검사마다 `standards`에 표준과 [표준 목록](../schemas/standards.json)의 항목을 붙인다. 모든 검사는 품질 모델(ISO/IEC 25010·25019·25012) 항목을 가진다. 실행 테스트에는 ISO/IEC/IEEE 29119-4 설계 기법, 인스펙션에는 ISO/IEC 20246 리뷰 항목, UX/UI 검사에는 ISO 9241의 해당 부, 인수·사용 맥락 검사에는 25019 또는 9241-11이 필요하다. 적용으로 표시한 항목 단위 표준에는 검사가 하나 이상 있어야 한다. `inspect`가 승인 전에, `verify`가 기록 시점의 표준 목록 사본으로 다시 확인한다.
- `project.py standards`가 판본과 항목 목록을 보여 준다. README의 '1.0 계획 옮기기'에 이전 절차를 적었다.
- Markdown·인쇄 HTML·리더 PDF는 같은 계산으로 표준·항목별 결과와 검사가 없는 평가 항목을 표시한다. 리플레이는 검사마다 적용 표준을 보여 준다.
- 선택하지 않은 검사(`selected: false`)도 표준을 붙이되, 적용 여부를 세지 않으므로 아직 적용하지 않은 판본을 쓸 수 있다. 적용 판본은 선택한 검사가 있어야 한다. UX/UI 규칙은 표준 목록에 있는 ISO 9241 부만 인정한다.
- 보고서와 리더 PDF는 시도의 `standards.json`이 승인 지문과 맞을 때만 항목별 대응을 표시하고, 맞지 않으면 '표준 목록 확인 필요'만 표시한다. 증거 2.0 기록에 2.1 전용 실행 경로 지문이 있으면 `verify`가 거부한다.
- 동봉 미리보기(`examples/preview`)는 RC.1 템플릿으로 만든 보존본이다. '적용 표준' 같은 새 화면 요소는 새로 렌더링한 보고서에서 확인한다.
- 표준 목록은 항목 이름과 그 근거 수준(`basis`)만 담는다. ISO/IEC/IEEE 29119-4:2021, ISO/IEC 20246:2017, ISO 9241-11:2018, ISO 9241-210:2019는 공식 미리보기 또는 목차 발췌, ISO/IEC 25010:2023, 25019:2023, 25012:2008, ISO 9241-110:2020은 공개 요약으로 이름을 확인했다. 나머지 판본은 항목 없이 부 단위로 붙인다. 이 목록은 평가 추적용이며 표준 준수나 인증을 뜻하지 않는다.

## Windows에서 확인한 범위

| Windows 11 · Python 3.11.9 / 3.12.7 · CP949 부모 환경 | 결과 |
|---|---|
| 일반 프로젝트 회귀 | 버전별 12/12 그룹. 표준 대응 규칙 위반 13건을 승인 전에 거부하고 보류 검사의 미적용 판본을 허용했다. 표준 목록 변조는 `verify`가 거부하고 보고서는 항목별 대응 대신 '표준 목록 확인 필요'를 표시했다. `standards` 목록 명령, 빈 판본·없는 판본 거부, 증거 2.0의 2.1 전용 필드 거부를 확인했다. |
| 합성 회귀·진행 관찰 | 버전별 5/5 그룹, 진행 관찰 10/10(실제 읽기 잠금 시험 포함) |
| 기록과 자체 검사 | 동봉 기록 7/7, ITR 자체 검사 계획 1.1의 실행·검증 통과 |
| 보고서 | 동봉 보고서 대조(PDF 포함)와 리플레이 DOM 통과. 리더 PDF는 계획 1.1 시도의 표준 대응 구간을 포함해 3.12에서 통과했고, PyMuPDF가 없는 3.11에서는 실행하지 않았다. |
| 배포 | 공식 릴리스 검사(`--root`) 버전별 통과 |

실제 브라우저 픽셀과 macOS는 이번 확인 범위 밖이다.
